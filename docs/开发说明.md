# 开发说明（给接手改这个 App 的人 / AI）

这是 `550-q/legado-mod-ziyongxiugai` 的定制版说明。上游是 [rimvoid/legado](https://github.com/rimvoid/legado)，
本仓库保留上游全部历史，改动集中在一个独立分支上。

## 0. 先看这三处

| 位置 | 内容 |
|---|---|
| `MODIFICATIONS.md` | 相对上游 v15 的全部改动，按功能分组，含文件清单 |
| `app/src/main/assets/updateLog.md` | App 内「更新日志」，顶部是最新版本条目（**只追加，不覆盖**） |
| `.github/workflows/build-apk.yml` | 云端打包流程（含签名参数，构建成功后自动发 Release） |

## 1. 分支约定

- `main`：等于上游 v15 的代码，只额外多 `build-apk.yml` 和本文件。**保持干净**，别把功能提交合进来——它是同步上游的锚点
- `mod/archive`：**所有功能改动在这里**，改代码请基于它
- **不要向上游 `rimvoid/legado` 提 PR，不要 force push**
- 远端约定：`origin` = 复刻仓库，`upstream` = `rimvoid/legado`（没配就 `git remote add upstream https://github.com/rimvoid/legado.git`）

⚠️ GitHub 首页的 **Sync fork** 按钮只更新 `main`，**不会同步到 `mod/archive`**，也无法在 `mod/archive` 上做「上游 + 我的改动」的合并。上游更新必须按第 6 节在本地 merge。

## 2. 构建（推荐走 GitHub Actions，不要本地打包）

仓库 → Actions → 左侧 **Build APK** → **Run workflow**：

- 分支选 `mod/archive`
- `version_code` 留空 = 自动生成；`version_name` 留空 = 自动 `3.26.MMDDHHmm`
- `abi` 选 `arm64-v8a`（默认；`armeabi-v7a` 仅备用）
- `create_release` 默认开：构建成功后自动发布到 Releases（tag = `apk-<versionCode>`，可点关）
- 约 7~25 分钟，产物在该次 run 页面底部 **Artifacts**（zip 内即 APK），同时出现在仓库 Releases

签名使用仓库内的 `app/ci-debug.keystore`，口令写在 workflow 文件里（与历史版本同一签名，可覆盖安装、不丢数据）。
包名 `io.legado.app.Archive`（applicationId `io.legado.app` + 后缀 `.Archive`，**不要改回** `io.legado.app`）。

## 3. 版本号规则（最容易踩坑）

- 自动值 = 当前 Unix 分钟数 + 10000000（约为 3990 万），单调递增
- **只增不减**：Android 不允许降级安装，新包 versionCode 必须 ≥ 手机已装版本（当前 `39928451`）
- 不超过 9 位数字
- 手动指定时，若在手机上打包，务必把 versionCode 填到 3990 万以上，否则装不上

## 5. 改代码时的硬性约定

1. `updateLog.md` 只在顶部**追加**新条目，别覆盖用户改过的正文
2. 新增文案要在四个语言包里同步：`values` / `values-zh` / `values-zh-rHK` / `values-zh-rTW`（缺 key 只回退英文，不报错，但仍要对齐）
3. 同一布局有 `layout/` 和 `layout-land/` 两份时，自定义控件必须两边一起改，否则 ViewBinding 类型退化成 `View`
4. Compose 读普通属性不会订阅变化：设置项要即时生效，得用 `mutableStateOf` + SharedPreferences 监听（模板 `FastScrollerConfig`）
5. `LazyColumn` 按 key 锚定：往列表前面插条目不会改变可视位置，需要显式 `scrollToItem(0)`
6. 居中/滚动要在布局完成后做（`pendingCenterIndex` + `addOnLayoutChangeListener`，参考 `RoundedTagBarView`）
7. Compose 快滚条里 `scrollPosition` 是「条目序号」不是 0~1 比例，别删换算
8. 选项卡配色：选中 = `accentColor`，未选中 = `primaryTextColor`/`secondaryTextColor`；`primaryColor` 深色主题下当文字色会发灰
9. `R.string.exit_no_save` 是全 App 共用的「未保存退出」提示，「是」= 继续编辑、「否」= 放弃并退出，不要翻转语义
10. Kotlin 默认参数 + 尾随 lambda：给方法加参数时，函数类型的参数保持在最后一位

## 6. 同步上游更新（**优先保留本仓库的修改**）

上游 `rimvoid/legado` 出新版时会改到很多与本仓库重叠的文件。同步的唯一目标是：**吃进上游的功能与修复，同时一条本地改动都不丢**。宁可在冲突处保留本地版本后手工补上游逻辑，也不要为了「干净」把本地改动覆盖掉。

### 6.1 三条前提

1. 同步**只在 `mod/archive` 上做**，用 `merge`，**不许 `rebase`**（rebase 会重写本地那十几个提交的哈希，历史对不上，以后无法追溯哪次改动来自哪个版本）
2. 同步前先确认工作区干净：`git status` 无未提交改动，否则先 stash 或提交
3. 上游有新版时先记下它的版本号（`Release Archive vXX (3.26.xxxx)`），同步完写进 `updateLog.md`

### 6.2 命令流程（在 `mod/archive` 上）

```bash
git checkout mod/archive
git status                      # 必须干净
git fetch upstream
git log --oneline mod/archive..upstream/main    # 先看清上游来了哪些提交
git merge upstream/main
# 出现冲突就按 6.3 处理，逐个 git add，最后
git commit                      # merge 提交
# 构建验证通过后再推
git push origin mod/archive
```

`main` 的处理：切到 `main` 后同样 `git merge upstream/main`（或直接用 GitHub 的 Sync fork 按钮），成功后 `main` 继续只保留 workflow 和本文件这两个自有文件。**不要**把 `mod/archive` 合进 `main`，也不要为了同步把 `main` 的成果再合回来——两个分支各走各的。

### 6.3 冲突处理优先级

| 冲突位置 | 处理原则 |
|---|---|
| 本地改过的功能文件（第 4 节地图里的 Kotlin/布局） | **保留本地实现**。上游在同一处有新逻辑时，把上游新增的部分手工并进本地代码，不要整体选「上游版本」 |
| `app/src/main/assets/updateLog.md` | 两边都要：保留本地全部旧条目，把上游新版本的条目插到本地条目前面 |
| `AndroidManifest.xml`、`app/build.gradle`、`gradle/`、依赖版本、`AGP`/`Kotlin` 版本 | **以上游为准**，这是构建基础设施；但要复查本地特有的东西没被冲掉：`applicationId` 后缀 `.Archive`、`ci-debug.keystore` 签名配置、只要 `arm64-v8a`、`versionCode` 不能被上游改小 |
| `values*/strings.xml` | 两边都要。上游新增的 key 全部保留；本地改过的同名 key 用本地文案（Kotlin 代码引用本地 key 时尤其注意） |
| `README.md`、`docs/`、`.github/` | 保留本地版本（本仓库自己的说明与打包流程） |
| 上游新增但本地没有的文件 | 一律接受上游版本 |

处理完再全仓扫一眼有没有残留冲突标记：

```bash
grep -rn "<<<<<<< \|>>>>>>> \|=======" --include=*.kt --include=*.xml --include=*.md --include=*.gradle . | head
```

### 6.4 同步后必须做的验证（不能省）

1. 走 Actions → **Build APK** → 分支 `mod/archive` → 版本号留空，**必须构建成功**。上游动过依赖或 Gradle 版本时，这里最容易炸，报错优先怀疑 6.3 表里「以上游为准」的那几项没对齐
2. 装机点一遍本地功能清单：快速滚动条与气泡、背书架分组居中与记忆、书籍详情目录打开方式、阅读跳转历史、朗读定时、正文长按条、添加本地先选分组、书架新书回顶
3. 版本号只增不减（见第 3 节），装不上就是这条被违背了
4. 全部正常后再更新 `MODIFICATIONS.md`（如果上游改动影响到了文件清单）

### 6.5 明确禁止

- 对 `mod/archive` 做 `rebase` 或 `force push`
- 用「选上游版本（theirs）」一次性解决本地功能文件的冲突
- 先合并 `mod/archive` → `main` 再去点 Sync fork
- 同步后不构建、不装机就直接推送

## 7. 已知未修问题

App 后台挂 1~2 小时后回到前台，**偶发**部分书架分组 /「我的」页上下滑完全无反应：条目仍可点击、左右切分组正常、顶栏正常、连滚动条气泡都不出现，重启可恢复。

- 已排除：`MainTopBarView` 吞触摸、`LockableViewPager` 脏 `mIsBeingDragged`、系统冻结、渲染管线卡死、单纯 Activity 重建
- 当前判断：要么列表视口/测量状态异常（Compose 判定 canScroll=false），要么手势被父容器（ViewPager/SwipeRefresh）吃掉
- 取证方式：在 `BooksFragment` / `MyFragment` 加只读手势探针（日志 tag 自定义），有 gesture 行且 `canF=false` → 视口问题；`canF=true` 但不动 → 手势节点问题；完全没有 gesture 行 → 手势没到列表
- 现场 10 秒判别：滑不动时切系统深色模式/切 tab/旋转屏幕，恢复 = 视图状态坏了，不恢复 = 手势被卡住

## 8. 不要提交的内容

构建产物、APK、`build/`、`.gradle/`、手机路径（`/sdcard/...`）、本机绝对路径、任何私人口令。
